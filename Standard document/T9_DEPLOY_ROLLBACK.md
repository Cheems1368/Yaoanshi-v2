# v0.1.0 部署与回退说明（待实测）

状态：仅开发/测试环境；未执行生产备份、清理、恢复或部署。发布前由部署负责人补齐实际环境、时间、操作者、备份位置和恢复演练记录。

## 部署前

1. 确认 PR C 已通过验收矩阵、保护检查、审核收敛并合并，`main` 六项 CI 全绿；随后等待 tag/Release 最终确认。
2. 记录当前服务镜像、Web 静态包和数据库 Flyway 版本，验证备份可读取且恢复步骤已演练。锁定停机/回退窗口。
3. 对将升级的真实库只读检查 `(tenant_id, plan_item_id, scheduled_at)` 上 `deleted=0` 的重复剂次；有重复时停止迁移并逐项处理，不批量删除或统一平移现有数据。
4. 通过受控环境变量提供数据库、对象存储和 `MEDICINE_OCR_API_KEY`；不得写入仓库或验收日志。OCR 默认模型为 `Qwen/Qwen3-VL-8B-Instruct`，部署前核对该模型在所用供应商账号下可用。确认上海业务时间、UTC 数据库连接和各端版本均为 `0.1.0`。

## 部署与验证

1. 先执行并核对 V15 Flyway 迁移；V1–V14 不修改。确认历史剂次、打卡和审计仍在，V15 唯一约束与新增表存在。
2. 部署后端、三个 Web 包，再分发与其匹配的 Android 包；逐项检查登录、计划启用/停用、打卡和离线重放、DDI、报表、催办、改派、通知断线补偿和 OCR。
3. 对 SEC-003 历史身份掩码和 SEC-005 过期 AI 审计数据，仅在单独批准的生产变更窗口、完成备份和留存核查后按既有脚本逐项清理。2026-09-24 的 MySQL/MinIO 隔离测试记录只能证明隔离环境行为；不得记为生产清理完成。清理前准备从备份恢复和验证的步骤。

## 阻断与回退

出现影响核心链路或数据正确性的阻断问题时，立即停止试点部署，保留错误日志和证据，恢复上一可用后端与 Web/Android 组合，验证登录、计划、剂次、打卡、工单和通知。V15 为附加式迁移，隔离库上先前本地后端镜像已在 V15 结构返回健康检查 200；这不替代真实环境的旧版应用兼容验证。回退期间保留 V15 列和历史记录，不对真实库执行 Flyway `clean` 或破坏性逆迁移。若数据库已受损，按部署前备份与演练步骤恢复并核对数据，再恢复服务。

保留既有 tag，不覆盖或删除；公告问题、影响范围、临时措施与后续修复版本。生产回退结果记录在正式变更单，不引用隔离测试作为生产执行证据。
