# 质量门禁规则配置

## 📋 门禁规则总览

质量门禁规则确保只有符合质量标准的代码才能合并到主分支，保障代码质量和项目稳定性。

## 🚫 禁止合并规则

### 1. 编译失败禁止合并
- **规则**: 任何编译错误或警告
- **检查点**: Maven编译阶段
- **阈值**: 0个编译错误，0个编译警告
- **执行**: `mvn compile -q`
- **失败条件**: 编译失败或存在警告

### 2. 单元测试失败禁止合并
- **规则**: 单元测试必须全部通过
- **检查点**: Maven测试阶段
- **阈值**: 100%测试通过率
- **执行**: `mvn test -q`
- **失败条件**: 任何测试失败

### 3. 静态检查失败禁止合并
- **规则**: 静态代码检查必须通过
- **检查点**: Checkstyle、SpotBugs、PMD检查
- **阈值**: 
  - Checkstyle: 0个违规
  - SpotBugs: 0个高优先级问题
  - PMD: 0个违规
- **执行**: 
  ```bash
  mvn checkstyle:check -q
  mvn spotbugs:check -q
  mvn pmd:check -q
  ```
- **失败条件**: 任何静态检查失败

### 4. 代码覆盖率不足禁止合并
- **规则**: 代码覆盖率必须达到阈值
- **检查点**: JaCoCo代码覆盖率检查
- **阈值**: ≥80%行覆盖率
- **执行**: `mvn jacoco:check -q`
- **失败条件**: 覆盖率低于80%

### 5. 安全漏洞禁止合并
- **规则**: 不允许存在安全漏洞
- **检查点**: OWASP依赖检查
- **阈值**: 0个高优先级漏洞
- **执行**: `mvn org.owasp:dependency-check-maven:check -q`
- **失败条件**: 存在CVSS评分≥7的漏洞

## ⚠️ 警告规则

### 1. 代码异味警告
- **规则**: 代码异味数量控制
- **阈值**: <10个代码异味
- **处理**: 记录警告，不阻止合并

### 2. 重复代码警告
- **规则**: 重复代码密度控制
- **阈值**: <3%重复代码密度
- **处理**: 记录警告，不阻止合并

### 3. 技术债务警告
- **规则**: 技术债务时间控制
- **阈值**: <30分钟技术债务
- **处理**: 记录警告，不阻止合并

## 🔧 门禁规则实现

### Jenkins Pipeline集成
```groovy
stage('质量门禁') {
    steps {
        script {
            // 编译检查
            sh 'mvn compile -q'
            
            // 单元测试
            sh 'mvn test -q'
            
            // 静态检查
            sh 'mvn checkstyle:check -q'
            sh 'mvn spotbugs:check -q'
            sh 'mvn pmd:check -q'
            
            // 代码覆盖率
            sh 'mvn jacoco:check -q'
            
            // 安全扫描
            sh 'mvn org.owasp:dependency-check-maven:check -q'
        }
    }
}
```

### Git Hooks集成
```bash
#!/bin/sh
# pre-commit hook

echo "执行质量门禁检查..."

# 编译检查
mvn compile -q
if [ $? -ne 0 ]; then
    echo "编译失败，禁止提交"
    exit 1
fi

# 单元测试
mvn test -q
if [ $? -ne 0 ]; then
    echo "单元测试失败，禁止提交"
    exit 1
fi

# 静态检查
mvn checkstyle:check -q
if [ $? -ne 0 ]; then
    echo "Checkstyle检查失败，禁止提交"
    exit 1
fi

echo "质量门禁检查通过"
exit 0
```

## 🚨 应急处理

### 门禁绕过流程
1. **申请**: 提交门禁绕过申请
2. **审批**: 技术负责人审批
3. **记录**: 记录绕过原因和时间
4. **修复**: 制定修复计划和时间表

### 紧急修复流程
1. **识别**: 快速识别问题根因
2. **修复**: 优先修复高优先级问题
3. **验证**: 验证修复效果
4. **合并**: 重新触发门禁检查
