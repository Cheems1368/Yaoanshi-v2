# 用药打卡系统设计方案

## 📋 项目概述

### 目标与范围
- **核心功能**: 用药提醒/打卡 + 关键健康数据记录
- **目标用户**: 慢性病患者（中老年群体）
- **业务闭环**: 记录→咨询的轻闭环，暂不涉及挂号/交易/配药
- **报告周期**: 默认每3个月生成用药与监测报告

### 用户角色
- **患者**: 操作极简，主要使用"提醒与打卡"入口
- **药师**: 关注依从性、异常中断、剂量匹配
- **医生**: 低频复核，快速掌握用药执行与关键指标
- **管理员**: 用户管理、角色权限、数据审计

## 🏗️ 系统架构

### 核心模块设计

#### 1. 用户与权限模块 (iam-auth)
- 账户管理、角色定义（患者/药师/医生/管理员）
- 机构来源标注（医院/社区）
- 数据域隔离：药师/医生仅能查看匹配患者数据

#### 2. 患者资料模块 (patients)
- 基本信息 + 过往病史（开放式必填）
- 结构化问卷答案存储
- 支持下拉/单选，减少开放填空

#### 3. 用药计划模块 (med-plans)
- 计划定义：药品/剂量/频次/时间点/餐前后/疗程
- 计划版本与变更记录
- 支持计划暂停/终止

#### 4. 打卡记录模块 (med-checkins)
- 实际服药时间、是否准时、补打原因
- 依从性指标计算（完成率、连续中断、迟服统计）
- 备注：不适/不良反应记录

#### 5. 指标记录模块 (measurements)
- 通用量表（血糖/血压/体重等）
- 区间提示，阈值占位字段
- 与打卡日期对齐，用于趋势分析

#### 6. 报告引擎模块 (reports)
- 报告周期策略（默认季度，可手动触发）
- 报告内容：病史摘要、用药依从性、关键指标趋势、异常摘要
- 导出格式：PDF/HTML，分享控制

#### 7. 质量门禁模块 (quality-gate)
- 静态代码检查（Checkstyle、SpotBugs、PMD）
- 测试覆盖率检查（JaCoCo）
- 安全扫描（OWASP依赖检查）
- CI/CD集成配置

#### 8. 提醒与任务模块 (reminders)
- 计划编排器（基于计划生成当天提醒任务）
- 渠道：APP内推送、短信/语音播报（预留）
- 失败重试与"未打卡"追踪

#### 9. 药师/医生池模块 (pro-pool)
- 人员基础信息、专科、来源机构标签
- 小规模固定配比与忙闲状态
- 简单匹配策略接口

#### 10. 审计与合规模块 (audit)
- 关键操作日志（计划变更、报告生成、权限分配）
- 数据留痕，满足医疗场景可追溯性要求

## 📊 数据模型设计

### 核心实体

#### Patient（患者）
```sql
- id: 患者ID
- basic_info: 基本信息（姓名、年龄、性别、联系方式）
- medical_history: 过往病史（开放式必填）
- questionnaire_answers: 结构化问卷答案
- created_at: 创建时间
- updated_at: 更新时间
```

#### MedPlan（用药计划）
```sql
- id: 计划ID
- patient_id: 患者ID
- plan_name: 计划名称
- start_date: 开始日期
- end_date: 结束日期
- status: 状态（active/paused/terminated）
- version: 版本号
- created_at: 创建时间
```

#### MedPlanItem（用药计划项）
```sql
- id: 计划项ID
- plan_id: 计划ID
- drug_name: 药品名称
- dosage: 单次剂量
- frequency: 频次
- time_points: 时间点
- meal_relation: 餐前后关系
- instructions: 用法说明
```

#### Checkin（打卡记录）
```sql
- id: 打卡ID
- plan_item_id: 计划项ID
- patient_id: 患者ID
- scheduled_time: 计划时间
- actual_time: 实际时间
- is_on_time: 是否准时
- is_makeup: 是否补打
- makeup_reason: 补打原因
- notes: 备注
- created_at: 打卡时间
```

#### Measurement（指标记录）
```sql
- id: 记录ID
- patient_id: 患者ID
- measurement_type: 指标类型（血糖/血压/体重等）
- value: 数值
- unit: 单位
- measurement_time: 测量时间
- notes: 备注
```

#### Report（报告）
```sql
- id: 报告ID
- patient_id: 患者ID
- report_period: 报告周期
- report_type: 报告类型（quarterly/manual）
- content: 报告内容（JSON格式）
- adherence_rate: 依从率
- key_indicators: 关键指标趋势
- anomalies: 异常摘要
- generated_at: 生成时间
- visible_to: 可见范围
```

## 🔌 API接口设计

### 患者侧接口

#### 用药计划管理
- `POST /api/patient/med-plans` - 创建用药计划
- `PUT /api/patient/med-plans/{id}` - 修改用药计划
- `POST /api/patient/med-plans/{id}/pause` - 暂停计划
- `POST /api/patient/med-plans/{id}/terminate` - 终止计划

#### 打卡功能
- `GET /api/patient/checkins/today` - 获取今日待打卡清单
- `POST /api/patient/checkins` - 提交打卡
- `POST /api/patient/checkins/{id}/makeup` - 补打卡

#### 指标记录
- `POST /api/patient/measurements` - 录入指标
- `GET /api/patient/measurements/trends` - 获取趋势数据
- `POST /api/patient/measurements/batch` - 批量导入

#### 报告查看
- `GET /api/patient/reports` - 查看历史报告
- `GET /api/patient/reports/{id}/download` - 下载报告

### 药师/医生侧接口

#### 患者管理
- `GET /api/professional/patients` - 获取匹配患者列表
- `GET /api/professional/patients/{id}/overview` - 患者总览
- `GET /api/professional/patients/{id}/details` - 患者详情

#### 报告管理
- `POST /api/professional/reports/generate` - 手动生成报告
- `GET /api/professional/reports` - 查看报告列表
- `PUT /api/professional/reports/{id}/notes` - 添加备注

#### 依从性监控
- `GET /api/professional/adherence/ranking` - 依从性排名
- `GET /api/professional/adherence/anomalies` - 异常列表

### 管理侧接口

#### 用户管理
- `GET /api/admin/users` - 用户列表
- `POST /api/admin/users` - 创建用户
- `PUT /api/admin/users/{id}/roles` - 分配角色

#### 系统管理
- `GET /api/admin/audit-logs` - 审计日志
- `GET /api/admin/system/health` - 系统健康检查

## 🚀 实施计划

### MVP阶段（本周内）
1. **患者资料模块**: 基本信息 + 病史必填
2. **用药计划模块**: 创建、修改、暂停/终止
3. **打卡记录模块**: 打卡提交、补打说明
4. **提醒任务模块**: 基于计划的提醒生成
5. **周期统计**: 依从性计算和基础趋势

### M1阶段（随后一周）
1. **指标记录模块**: 录入与区间提示
2. **报告引擎**: 自动调度与分享控制
3. **匹配池管理**: 来源标签与忙闲控制
4. **审计日志**: 关键操作记录
5. **接口压测**: 性能基线测试

## 🔧 技术实现要点

### 数据库设计
- 使用MySQL 8.0，支持JSON字段存储复杂数据
- 建立合适的索引，优化查询性能
- 考虑数据分区，支持大数据量场景

### 缓存策略
- 使用Redis缓存热点数据（患者信息、用药计划）
- 缓存依从性统计结果，减少重复计算
- 设置合理的过期时间

### 安全考虑
- 数据加密存储敏感信息
- 接口访问控制，基于角色的权限管理
- 操作日志记录，满足合规要求

### 性能优化
- 异步处理报告生成任务
- 批量操作支持，减少数据库交互
- 分页查询，避免大数据量查询
