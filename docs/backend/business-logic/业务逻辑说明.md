# 后端业务逻辑说明

## 系统架构概述

本系统是一个医疗HIS配送管理系统，采用分层架构设计，主要服务于药学服务、患者管理、处方审核等医疗业务场景。系统面向慢性病为主的中老年患者群体，支持"药师首诊、医生终审"的业务闭环，主要包含以下模块：

### 核心模块

1. **系统模块 (medicine-module-system)**
   - 用户认证与授权
   - 工单管理
   - 系统配置管理

2. **患者模块 (medicine-module-patient)**
   - 患者信息管理
   - 门诊管理
   - 住院管理
   - 处方管理

3. **药品模块 (medicine-module-drug)**
   - 药品信息管理
   - 药品库存管理

4. **用药模块 (medicine-module-medication)**
   - 用药计划管理
   - 用药打卡
   - 用药提醒

5. **医生模块 (medicine-module-doctor)**
   - 医生信息管理
   - 医生排班管理

## 主要业务逻辑

### 1. 用户认证流程

**功能描述**：用户登录、登出、权限验证

**核心流程**：
1. 用户输入用户名和密码
2. 验证码校验（可选）
3. 验证用户账号和密码
4. 检查用户状态（是否禁用）
5. 创建访问令牌（OAuth2 Token）
6. 记录登录日志
7. 返回登录结果（包含 accessToken 和 refreshToken）

**关键组件**：
- `AuthController`：认证控制器
- `AdminAuthService`：认证服务
- `AdminUserService`：用户服务
- `OAuth2TokenService`：令牌服务
- `LoginLogService`：登录日志服务

### 2. 工单处理流程

**功能描述**：患者提交求助工单，药师和医生协作处理

**核心流程**：
1. 患者提交工单（包含症状、需求药品等信息）
2. 工单状态：SUBMITTED（已提交）
3. 药师认领工单，状态变为：ASSIGNED_PHARMACIST（已分配药师）
4. 药师审核，状态变为：PHARMACIST_REVIEW（药师审核中）
5. 如果需要医生介入，升级到医生，状态变为：TO_DOCTOR（转医生）
6. 医生处理，状态变为：DOCTOR_REVIEW（医生审核中）
7. 医生开具处方，状态变为：PRESCRIPTION_READY（处方就绪）
8. 工单完成，状态变为：DONE（已完成）
9. 或者工单被驳回，状态变为：REJECTED（已驳回）

**关键组件**：
- `HelpOrderController`：工单控制器
- `HelpOrderService`：工单服务
- `HelpOrderDO`：工单数据对象
- `HelpOrderStatus`：工单状态枚举

### 3. 处方管理流程

**功能描述**：医生开具电子处方，药师配药，患者取药

**核心流程**：
1. 医生创建处方（基于工单或直接创建）
2. 处方状态：draft（草稿）
3. 医生确认并签名，状态变为：confirmed（已确认）
4. 药师审核处方，状态变为：signed（已签名）
5. 药师配药，配药状态：dispensed（已配药）
6. 患者取药，配药状态：picked_up（已取药）
7. 处方完成，状态变为：completed（已完成）

**关键组件**：
- `ElectronicPrescriptionController`：电子处方控制器
- `ElectronicPrescriptionService`：电子处方服务
- `PrescriptionsController`：处方控制器
- `PrescriptionsService`：处方服务

### 4. 用药计划管理流程

**功能描述**：为患者创建用药计划，生成每日待办任务，患者打卡记录

**核心流程**：
1. 创建用药计划（包含计划名称、开始日期、结束日期）
2. 添加用药计划项（药品、剂量、频次、时间）
3. 生成今日待办任务（基于计划项计算）
4. 患者查看待办任务
5. 患者提交用药打卡
6. 验证打卡记录
7. 更新任务状态

**关键组件**：
- `MedPlanController`：用药计划控制器
- `MedPlanService`：用药计划服务
- `MedCheckinService`：用药打卡服务
- `TodayTaskService`：今日待办服务

### 5. 患者管理流程

**功能描述**：患者信息管理、门诊记录、住院记录

**核心流程**：
1. 患者注册/创建患者档案
2. 患者审核（如果需要）
3. 创建门诊记录（包含检查、教育、药品、检验）
4. 创建住院记录（包含医嘱、教育、评估、查房、会诊）
5. 创建家庭记录（包含咨询、教育、评估、用药）

**关键组件**：
- `PatientsController`：患者控制器
- `OutpatientService`：门诊服务
- `InpatientService`：住院服务
- `HomeService`：家庭服务

### 6. 药品管理流程

**功能描述**：药品信息管理、药品查询

**核心流程**：
1. 管理员创建药品信息
2. 更新药品信息
3. 查询药品列表（支持分页、筛选）
4. 根据药品名称查询
5. 导出药品信息

**关键组件**：
- `DrugsController`：药品控制器
- `DrugsService`：药品服务
- `DrugsDO`：药品数据对象

## 数据流转

### 典型业务流程

1. **患者求助流程**：

   ```text
   患者 → 提交工单 → 药师审核 → 医生处理 → 开具处方 → 药师配药 → 患者取药
   ```

2. **用药管理流程**：

   ```text
   医生 → 创建用药计划 → 生成待办任务 → 患者打卡 → 验证打卡 → 更新状态
   ```

3. **处方流转流程**：

   ```text
   医生 → 创建处方 → 确认签名 → 药师审核 → 配药 → 患者取药 → 完成
   ```

## 技术特点

1. **分层架构**：Controller → Service → Mapper → Database
2. **事务管理**：使用 `@Transactional` 保证数据一致性
3. **权限控制**：使用 Spring Security 和 `@PreAuthorize` 注解
4. **状态机管理**：工单和处方使用状态机管理状态流转
5. **JSON 字段处理**：使用 JSON 存储复杂结构数据（如药品列表、附件）
6. **性能优化**：使用缓存、批量查询优化、性能监控
