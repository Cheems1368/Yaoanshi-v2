# 故障排查手册

## 🚨 用药打卡系统故障排查指南

### 📋 故障分类

#### 1. 系统级故障
- **服务不可用**: 应用无法启动或响应
- **数据库连接失败**: 无法连接MySQL数据库
- **Redis连接失败**: 无法连接Redis缓存
- **内存溢出**: JVM内存不足

#### 2. 业务级故障
- **工单处理异常**: 工单状态流转失败
- **患者数据异常**: 患者信息丢失或错误
- **用药计划异常**: 用药计划计算错误
- **权限验证失败**: 用户无法正常登录

#### 3. 性能级故障
- **响应时间过长**: API响应超过阈值
- **并发处理能力不足**: 高并发下系统崩溃
- **数据库性能问题**: 查询执行缓慢
- **缓存命中率低**: Redis缓存效率低下

## 🔍 故障排查流程

### 步骤1: 快速诊断

#### 1.1 服务状态检查
```bash
# 检查所有服务状态
docker compose ps

# 检查特定服务状态
docker ps | grep medicine

# 检查服务健康状态
curl http://localhost:48080/actuator/health
```

#### 1.2 基础连通性测试
```bash
# 测试应用端口
telnet localhost 48080

# 测试数据库端口
telnet localhost 13306

# 测试Redis端口
telnet localhost 16379
```

### 步骤2: 详细诊断

#### 2.1 应用日志分析
```bash
# 查看实时日志
docker logs -f medicine-server

# 查看错误日志
docker logs medicine-server 2>&1 | grep -i error

# 查看特定时间段的日志
docker logs --since 1h medicine-server

# 查看最近的日志
docker logs --tail 100 medicine-server
```

#### 2.2 系统资源检查
```bash
# 检查CPU使用率
docker stats medicine-server

# 检查内存使用情况
docker exec medicine-server free -h

# 检查磁盘空间
docker exec medicine-server df -h
```

### 步骤3: 深度分析

#### 3.1 数据库诊断
```bash
# 检查数据库连接数
docker exec -it medicine-mysql mysql -uroot -p123456 -e "SHOW STATUS LIKE 'Threads_connected'"

# 检查慢查询
docker exec -it medicine-mysql mysql -uroot -p123456 -e "SHOW VARIABLES LIKE 'slow_query_log'"

# 检查数据库锁
docker exec -it medicine-mysql mysql -uroot -p123456 -e "SHOW PROCESSLIST"
```

#### 3.2 Redis诊断
```bash
# 检查Redis连接
docker exec -it medicine-redis redis-cli ping

# 检查Redis内存使用
docker exec -it medicine-redis redis-cli info memory

# 检查Redis键数量
docker exec -it medicine-redis redis-cli dbsize
```

## 🛠️ 常见故障解决方案

### 故障1: 应用启动失败

#### 症状
- Docker容器启动后立即退出
- 应用日志显示启动异常
- 健康检查失败

#### 排查步骤
```bash
# 1. 检查容器状态
docker ps -a | grep medicine-server

# 2. 查看启动日志
docker logs medicine-server

# 3. 检查配置文件
docker exec medicine-server cat /app/application.yml

# 4. 检查环境变量
docker exec medicine-server env | grep -E "(MYSQL|REDIS|JAVA)"
```

#### 解决方案
1. **配置错误**: 检查application.yml配置
2. **端口冲突**: 检查端口占用情况
3. **依赖缺失**: 检查数据库和Redis连接
4. **内存不足**: 调整JVM内存参数

### 故障2: 数据库连接失败

#### 症状
- 应用日志显示数据库连接异常
- 健康检查显示数据库DOWN
- 业务功能无法正常使用

#### 排查步骤
```bash
# 1. 检查数据库服务状态
docker ps | grep mysql

# 2. 检查数据库连接
docker exec -it medicine-mysql mysql -uroot -p123456 -e "SELECT 1"

# 3. 检查网络连通性
docker exec medicine-server ping medicine-mysql

# 4. 检查连接池配置
curl http://localhost:48080/actuator/metrics/hikaricp.connections.active
```

#### 解决方案
1. **数据库服务未启动**: 重启MySQL容器
2. **连接池耗尽**: 调整连接池配置
3. **网络问题**: 检查Docker网络配置
4. **认证失败**: 检查用户名密码配置

### 故障3: Redis连接失败

#### 症状
- 应用日志显示Redis连接异常
- 缓存功能失效
- 会话管理异常

#### 排查步骤
```bash
# 1. 检查Redis服务状态
docker ps | grep redis

# 2. 检查Redis连接
docker exec -it medicine-redis redis-cli ping

# 3. 检查Redis内存使用
docker exec -it medicine-redis redis-cli info memory

# 4. 检查Redis配置
docker exec medicine-redis redis-cli config get "*"
```

#### 解决方案
1. **Redis服务未启动**: 重启Redis容器
2. **内存不足**: 调整Redis内存配置
3. **配置错误**: 检查Redis连接配置
4. **网络问题**: 检查Docker网络配置

### 故障4: 性能问题

#### 症状
- API响应时间过长
- 系统响应缓慢
- 用户操作卡顿

#### 排查步骤
```bash
# 1. 检查JVM内存使用
curl http://localhost:48080/actuator/metrics/jvm.memory.used

# 2. 检查GC情况
curl http://localhost:48080/actuator/metrics/jvm.gc.pause

# 3. 检查HTTP请求指标
curl http://localhost:48080/actuator/metrics/http.server.requests

# 4. 检查数据库性能
docker exec -it medicine-mysql mysql -uroot -p123456 -e "SHOW STATUS LIKE 'Slow_queries'"
```

#### 解决方案
1. **内存不足**: 调整JVM内存参数
2. **GC频繁**: 优化GC配置
3. **慢查询**: 优化SQL查询
4. **连接池不足**: 调整连接池配置

## 📊 监控指标说明

### 关键指标阈值

#### 系统指标
- **CPU使用率**: < 70%
- **内存使用率**: < 80%
- **磁盘使用率**: < 85%
- **网络延迟**: < 100ms

#### 应用指标
- **响应时间**: p95 < 300ms
- **错误率**: < 1%
- **吞吐量**: > 100 req/s
- **并发数**: < 1000

#### 数据库指标
- **连接数**: < 80% 最大连接数
- **慢查询**: < 1%
- **锁等待**: < 100ms
- **缓存命中率**: > 95%

#### Redis指标
- **内存使用率**: < 80%
- **命中率**: > 95%
- **连接数**: < 100
- **响应时间**: < 1ms

## 🚨 紧急故障处理

### 紧急故障类型
1. **服务完全不可用**
2. **数据丢失或损坏**
3. **安全漏洞**
4. **性能严重下降**

### 紧急处理流程
1. **立即隔离**: 停止受影响的服务
2. **快速诊断**: 使用自动化脚本快速定位问题
3. **临时修复**: 实施临时解决方案
4. **通知相关人员**: 及时通知开发团队和用户
5. **详细分析**: 深入分析根本原因
6. **永久修复**: 实施永久解决方案
7. **事后总结**: 编写故障报告和改进措施

### 紧急联系方式
- **开发团队**: 24小时值班电话
- **运维团队**: 紧急响应群
- **用户支持**: 客服热线
