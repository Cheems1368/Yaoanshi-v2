Real OCR Feedback Plan (2026-04-28)
- current finding:
  - Patient prescription upload currently registers the object key only; it does not PUT the selected image bytes to MinIO/S3.
  - Backend OCR currently receives a presigned URL based on the internal Docker MinIO host (`http://minio:9000/...`), which external OCR providers cannot fetch.
  - Therefore real OCR cannot produce useful feedback yet and falls back to low-confidence manual review.
- chosen approach:
  - Patient app will PUT the selected image bytes to the presigned upload URL before calling prescription registration.
  - Backend will read the uploaded object bytes from MinIO/S3 by object key.
  - OCR request will send the image as base64/data URL content instead of asking the OCR provider to fetch a local MinIO URL.
- constraints:
  - `MEDICINE_OCR_API_KEY` must be supplied only through environment variables or approved secret tooling.
  - Do not write OCR secrets, tokens, private keys, or `.env` values into code, docs, progress notes, or logs.
  - Demo patient identity must not be hardcoded; use the actual on-site test patient selected for the walkthrough.
- next:
  - Add true frontend upload PUT, object storage byte-read support, OCR base64 forwarding, adb reverse for port 9000, and targeted backend/frontend verification.
  - Then validate on a real phone by confirming the uploaded object exists in MinIO and the patient/pharmacist screens show real OCR status and confidence.
