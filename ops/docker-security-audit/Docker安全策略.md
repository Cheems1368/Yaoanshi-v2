# Docker安全策略文档

**版本**: 1.0  
**生效日期**: 2025-01-27  
**适用范围**: 药学管理系统 (medicinal-his-delivery)

## 📋 策略概述

本文档制定了药学管理系统Docker容器化部署的安全策略，确保容器环境的安全性、稳定性和合规性。

## 🎯 安全目标

1. **容器安全**: 确保容器镜像和运行环境安全
2. **数据保护**: 保护敏感数据和配置信息
3. **网络安全**: 确保容器间通信安全
4. **资源控制**: 防止资源滥用和攻击
5. **合规性**: 满足医疗行业安全合规要求

## 🔒 安全策略

### 1. 镜像安全策略

#### 1.1 基础镜像要求
- ✅ 使用官方认证的基础镜像
- ✅ 优先选择Alpine Linux等轻量级发行版
- ✅ 定期更新基础镜像到最新稳定版本
- ❌ 禁止使用root用户运行应用
- ❌ 禁止使用包含已知漏洞的镜像

#### 1.2 镜像构建要求
```dockerfile
# 必须使用多阶段构建
FROM maven:3.8-openjdk-11-slim AS builder
# ... 构建阶段

FROM eclipse-temurin:11-jre-alpine:latest
# ... 运行阶段

# 必须创建非root用户
RUN addgroup -g 1001 -S appgroup && \
    adduser -u 1001 -S appuser -G appgroup
USER appuser
```

#### 1.3 镜像扫描要求
- 每次构建后必须进行安全扫描
- 高危漏洞必须修复后才能部署
- 中危漏洞应在7天内修复
- 低危漏洞应在30天内修复

### 2. 容器运行时安全策略

#### 2.1 用户权限
```yaml
# 必须配置非特权用户
security_opt:
  - no-new-privileges:true
user: "1001:1001"
```

#### 2.2 文件系统安全
```yaml
# 只读根文件系统
read_only: true
tmpfs:
  - /tmp
  - /var/run
```

#### 2.3 资源限制
```yaml
# 必须配置资源限制
deploy:
  resources:
    limits:
      cpus: '2.0'
      memory: 2G
    reservations:
      cpus: '1.0'
      memory: 1G
```

### 3. 网络安全策略

#### 3.1 网络隔离
- 使用自定义Docker网络
- 禁止使用host网络模式
- 容器间通信必须通过内部网络

#### 3.2 端口暴露
```yaml
# 最小化端口暴露
ports:
  - "48080:48080"  # 仅暴露必要端口
# 禁止暴露数据库端口到宿主机
```

#### 3.3 网络策略
- 使用非标准端口映射
- 配置防火墙规则
- 启用网络加密（TLS/SSL）

### 4. 数据安全策略

#### 4.1 敏感信息管理
```yaml
# 使用Docker secrets管理敏感信息
secrets:
  db_password:
    file: ./secrets/db_password.txt
  redis_password:
    file: ./secrets/redis_password.txt
```

#### 4.2 数据卷安全
- 使用命名卷而非绑定挂载
- 设置适当的文件权限
- 定期备份重要数据

#### 4.3 环境变量安全
- 敏感信息不得通过环境变量传递
- 使用配置文件或secrets管理
- 定期轮换密码和密钥

### 5. 监控和日志策略

#### 5.1 健康检查
```yaml
# 必须配置健康检查
healthcheck:
  test: ["CMD", "curl", "-f", "http://localhost:48080/actuator/health"]
  interval: 30s
  timeout: 10s
  retries: 3
  start_period: 60s
```

#### 5.2 日志管理
```yaml
# 配置日志轮转
logging:
  driver: "json-file"
  options:
    max-size: "10m"
    max-file: "3"
```

#### 5.3 监控要求
- 监控容器资源使用情况
- 监控容器健康状态
- 设置告警机制

## 📚 最佳实践

### 1. 镜像构建最佳实践
- 使用.dockerignore减少构建上下文
- 利用Docker层缓存优化构建速度
- 定期清理未使用的镜像和层
- 使用多阶段构建减少最终镜像大小

### 2. 容器运行最佳实践
- 一个容器只运行一个进程
- 使用非root用户运行应用
- 配置适当的资源限制
- 启用健康检查和自动重启

### 3. 网络安全最佳实践
- 使用最小权限原则
- 定期更新网络配置
- 监控网络流量
- 使用TLS加密通信

## 🚨 应急响应

### 安全事件分类
1. **P0 - 严重**: 数据泄露、系统被攻破
2. **P1 - 高**: 高危漏洞、服务不可用
3. **P2 - 中**: 中危漏洞、性能问题
4. **P3 - 低**: 低危漏洞、配置问题

### 响应流程
1. **发现**: 监控告警或人工发现
2. **评估**: 确定事件等级和影响范围
3. **响应**: 执行相应的应急措施
4. **恢复**: 修复问题并恢复正常服务
5. **总结**: 分析原因并改进安全措施
